# HAP 私有部署交付文档

根据用户选择生成单份、架构图或整套交付件。保留现有封面、字体、表格、代码块及渲染管线；技术内容以本次读取的官方资料和项目明确覆盖为依据。

## 先确定本次范围

- 从对话、入参 Excel、网络申请单提取所需产物、部署形态、节点、IP、端口、组件和迁移范围；只补问影响结果的缺失信息。
- 入参 Excel 必须先读取最后一个 Sheet「自定义项描述」，将项目约束落实后再生成。网络申请单不是固定入参模板，先整理为入参或项目架构 SVG。
- 明确纠正的信息覆盖早期输入。已确认的值不再标“待确认”；未给出的角色、VIP、域名和集群模式不得由单个地址推定。
- 客户标识、真实凭据和具体项目覆盖不得提交到技能仓库；项目指定版本、端口、信创替换、云平台、服务包含关系只作用于该项目。

## 可选模块（默认无）

入参新增「⑦ 可选模块」，最后的自定义项描述仍保留在最后一页。新增技术能力、数据库替代模式、实施进度表和业务功能验证记录均预填「无」；旧入参缺少该页时全部视为未选，不根据用户数、部署档次或官网栏目自动启用。

以对话收集入参时，同样一次展示可选清单并说明默认无；用户未选择的项保持无，不阻塞原有交付范围。提供 Excel 时直接使用其下拉选项。

- 用户启用某项后，读取 [可选模块交付规则](reference/optional-modules.md)，按所选模式读取当前官网及适用性说明；由执行本 skill 的助手编写本项目完整章节和关联交付内容。不得只补链接、提纲或历史版本号。
- 预检自动按所选模块采集来源；技术模块的项目内容 JSON 由助手完成后通过 `seal --module-content 项目目录/可选模块内容.json` 绑定。缺章节/依赖/节点/自定义架构图时先完成这些工作，不能直接声称已支持或绕过门禁。
- 只生成用户选择的产物；可选模块章节随对应部署、运维、FAQ、资源、凭据和清单输出。实施进度表随 `deploy` 输出，功能验证记录随 `deploy` 或 `checklist` 输出，均由选项启用后才生成。
- 数据库替代模式需整体修订相关文档、凭据和项目 SVG，不能在原 MGR/哨兵正文后简单追加一套相互冲突的步骤。MongoDB 8.3 先核对迁移/共置/各环境版本限制；历史 EOL 模式仅在入参明确选择并说明适用原因时采用。
- 公有云迁移到私有部署不在本次扩展范围内；不增加其选项或生成器。新增模块的密码/AK/SK/Webhook 只从入参凭据页写入凭据表，项目内容 JSON、正文和来源记录保留占位符。

## 实时发现与最新组件版本

每次生成前先从官方总入口发现本次相关页面，再读取组件专属页；`reference/source-map.md` 是发现线索，不是冻结的链接或版本清单。

1. 读取集群部署总入口与通用组件/资源入口，根据本次部署形态发现对应子页。核对版本页、单节点/集群模式与适用架构；链接变更时更新本次来源记录，不能因旧链接失效就默认用旧内容。
2. 默认使用 **HAP 官方当前说明中的最新适用组件版本及对应安装链接**。同时提取页面明示的版本、镜像标签和安装包；不得从历史模板或第三方搜索摘要猜版本，也不得把未经 HAP 文档确认的上游最新版直接混入。
3. 项目明确锁定版本时记录原因和相应官方链接。专属安装页与汇总页冲突时列明差异，解决后再生成，不静默选择或混用。
4. 核对安装包的系统/CPU 架构，并联动更新下载、解压、配置、systemd、初始化和验证步骤；不能只替换版本号。
5. 更新对应基线并核验后再登记完成。通过来源检查不代表旧基线已经更新，或代表下载包已安装验证。

来源优先级：项目明确覆盖 → 当前组件专属官方页 → 官方汇总页交叉核对 → 页面无法访问时才使用标明日期的历史缓存。

## 实际执行与生成门禁

脚本使用标准库直接读取官网；环境禁止直接访问时，改用当前可用的浏览工具采集同一批页面，保存正文、链接和本次采集时间，再导入预检。浏览工具是网络通道替代，不是跳过预检的理由。

```text
python scripts/make_input_template.py 入参模板.xlsx
python scripts/source_preflight.py prepare --version std --outputs deploy,ops,arch,cred,faq,resource,checklist --input 已填入参.xlsx --report 项目目录/来源核验.json
# 读取来源记录及对应正文，按发现的版本/链接完整更新受影响基线，落实项目自定义项。
python scripts/source_preflight.py seal --report 项目目录/来源核验.json --note "已核对来源、版本、安装步骤、版式和本项目覆盖"
python scripts/gen_from_input.py 已填入参.xlsx 项目目录 --only deploy,ops,arch,cred,faq,resource,checklist --preflight 项目目录/来源核验.json
```

- `prepare` 只采集和比较，不自动把网上命令写入部署基线；`seal` 检查来源快照、版本落后情况并绑定当前基线和入参。生成器会检查核验记录、范围、时间、基线及入参，缺失/过期/改变后不能直接生成。
- 浏览采集格式与离线处理见 [reference/preflight.md](reference/preflight.md)。只有页面确实无法读取时才使用 `--allow-offline`；产物目录必须附带缺失来源、缓存日期和未核验范围，不声称已按最新版生成。
- `--only` 可选 `deploy,ops,migration,arch,cred,faq,resource,checklist`；不选 migration 就不生成迁移文档。默认整套不含迁移，需要时明确加入。
- 单独调用 `gen_deploy.py` 等生成器时，也必须设置 `HAP_PREFLIGHT_REPORT`，并将 `HAP_DELIVERY_INPUT` 设为对应入参路径（无入参的占位版可不设）；本次项目范围以核验记录为准。
- 不联网的样例/测试同样使用明确离线记录，禁止在发布或真实交付中绕过门禁。

## 项目参数与架构图

- 沿用入参 Excel 的项目信息、节点 IP 与凭据清单；密码只填入凭据表，部署/运维正文保留 `<强密码>`。实际密码不进入日志或来源记录。
- 特殊组件、排除项和端口修改需要在项目副本的基线中完整落实，核对各文档、架构图和清单一致。不要将项目值改成通用默认。
- 只需架构图时可使用 `--only arch --architecture 项目架构.svg`；基于实际输入制作该 SVG，预检绑定它的哈希，生成时按同一文件导出 PNG。不得套用与实际节点数不符的标准版/专业版示意图。
- 架构图默认白底、浅灰蓝、深色文字、清晰箭头；多组件调用优先一条主干连接共享总线，分别短箭头指向组件；说明箭头表达请求方向还是数据方向。
- 按项目要求表达内置服务、独立服务、托管组件和网络边界。AKS、Teams/SSO、客户端口或去除某边框都不是全局默认。
- 默认架构生成器只提供历史标准拓扑示意，不代表当下官方推荐节点数或任一客户真实部署。缺少实际参数时必须标明示意，版本/数量以本次来源和节点清单核定。

## 交付前检查

- 本次相关总入口和组件页已读取，组件版本、包/镜像、配置及命令一致；冲突已处理，离线部分单列。
- 节点总数按实际节点去重统计，不能混用历史的 26 / 29 等口径；不推定未给出的主从、哨兵或副本集。
- IP、端口、域名、包含关系和请求方向与用户最后确认一致；可选组件的排除同步到所有产物。
- 文件名去掉内部场景 A/B 标识；清单只引用本次实际生成的文件，不包含未选择的迁移文档。
- 检查 Word 表格、代码块、链接和架构图的文字/连线排版；报告实际运行的验证及未核验范围。
